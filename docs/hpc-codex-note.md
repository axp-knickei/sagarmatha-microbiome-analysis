# FMIPA UB / Nebula HPC Operational Reference

> Purpose: operational reference for researchers and coding agents preparing shell commands, PBS jobs or optional interactive workflows in the FMIPA UB/Nebula HPC environment.
> Audience: users of this cluster; the workflow-specific guides remain authoritative for analytical inputs, methods and execution.
> Source: `260630_HPC_MIPA_manual.pdf` — Panduan Penggunaan Dasar Server HPC FMIPA UB, Tim HPC FMIPA UB 2024 / Rilis 2.0.

The source manual and its node/module examples are historical records, not a
verified current cluster inventory or a list of analytical dependencies. Check
current site documentation and available modules before using them. The public
archive does not require access to the source manual to run the documented code.

OpenPBS commands below apply to this cluster. Other supported environments may
use the repository's separate Slurm launchers or run locally without a scheduler.
Use the [HPC index](../hpc/README.md), [release workflow](public-workflow.md) and
[environment guide](public-environment.md) for the released analytical workflows.

## Cluster operating rules

- Treat `<hpc-login-node>` as the SSH gateway/login node.
- Do not run heavy computation directly on `<hpc-login-node>`.
- Submit compute jobs through OpenPBS using `qsub`.
- Start job scripts with `cd $PBS_O_WORKDIR` so execution occurs in the submission directory.
- Use Environment Modules for system-provided software; inspect before loading.
- Use placeholders for private account-specific values. Never invent username, gateway IP, email, token, or password.
- Prefer small test jobs before full analysis jobs.
- For MPI jobs, set `OMP_NUM_THREADS=1` unless the workflow explicitly mixes MPI + OpenMP.
- Keep stdout/stderr files generated by PBS for debugging.

## Cluster Access

SSH access is through a user-defined gateway alias such as `<hpc-login-node>`. Private connection values belong in a local ignored file, not in public documentation.

Recommended local SSH config template:

```sshconfig
Host <hpc-login-node>
    Port <SSH_PORT>
    User <HPC_USERNAME>
    HostName <HPC_GATEWAY_PUBLIC_IP_OR_HOSTNAME>
    IdentityFile <SSH_PRIVATE_KEY_PATH>
    IdentitiesOnly yes
    ServerAliveInterval 30
    ServerAliveCountMax 1000
```

Login command:

```bash
ssh <hpc-login-node>
```

SSH key setup expected by manual:

```bash
ssh-keygen -t rsa
cat ~/.ssh/id_rsa.pub
```

Use the public key content for the account/application form. Do not regenerate keys casually after submission because the old registered key may stop matching.

### SSH-agent use

For this site's access route, connect to the UB VPN first, as described in the
[result-transfer guide](nebula-results-download.md). If the registered private
key is passphrase-protected, load the existing key into an SSH agent in the local
terminal before connecting. Reuse an available agent; start one only if needed.

```bash
# Start an agent only when one is not already available in this terminal:
eval "$(ssh-agent -s)"
# Replace the placeholder with the existing registered key path:
ssh-add "<SSH_PRIVATE_KEY_PATH>"
# Replace the placeholder with the configured local SSH alias:
ssh "<hpc-login-node>"
```

Enter the passphrase at the local prompt; do not put it in scripts, logs or
public documentation. Starting an agent or loading a key does not register a
new key with the cluster. Keep account-specific SSH configuration and access
notes local; do not regenerate the registered key to resolve an agent problem.

## Environment Modules

Always inspect module availability inside the HPC environment before assuming exact software names/versions.

```bash
module avail
module list
module purge
module load <module_name>/<version>
module unload <module_name>/<version>
module switch <old_module> <new_module>
```

Historical example modules from the manual (not BlackICE dependencies):

```bash
module load lammps/020823
# Auto-loads example dependencies:
# openmpi/5.0.0 fftw/3.3.10d kim/2.2.1 hdf5/1.14.2 lapack/3.11.0
```

Known module examples visible in manual include `intelpython/2022.2.0`, `openmpi/5.0.0`, `gromacs/2018.8d`, `lammps/020823`, `autodock-suite/4.2.6`, and `autodock-vina/1.2.5`. Verify with `module avail` before using.

The tracked Nebula wrappers default to `intelpython/2022.2.0` as the Conda-providing module. Verify its availability; use the documented module/environment overrides when required:

```bash
module purge
module load intelpython/2022.2.0
conda run -n glmm-hpc Rscript scripts/summarize_hpc_candidate_signals.R
```

## OpenPBS Commands

Submit:

```bash
qsub <job_script.sh>
```

Monitor:

```bash
qstat
qstat -n
qstat -s
```

Cancel:

```bash
qdel <JOB_ID>
```

Common status codes:

| Code | Meaning |
|---|---|
| `Q` | queued |
| `R` | running |
| `E` | exiting/completed and finalizing |
| `H` | held |
| `S` | suspended/held by server priority |
| `T` | transitioning |
| `U` | user-held |

## PBS Script Templates

### Minimal smoke test

Use this before expensive workflows.

```bash
#!/bin/bash
#PBS -N smoke_test
#PBS -l select=1:ncpus=1
#PBS -M <EMAIL>
#PBS -m abe

cd $PBS_O_WORKDIR

echo "stdout: PBS job started on $(hostname)"
echo "stderr: diagnostic message" 1>&2
echo "host=$(hostname)" > result.txt
```

Run:

```bash
qsub smoke_test.sh
qstat -n
```

Expected outputs include PBS `.o<jobid>` and `.e<jobid>` files plus `result.txt`.

### Single-node CPU job using virtual/thread processor syntax

Use when requesting logical CPU slots through `select=1:ncpus=<N>`.

```bash
#!/bin/bash
#PBS -N <JOB_NAME>
#PBS -l select=1:ncpus=<NCPUS>
#PBS -M <EMAIL>
#PBS -m abe

cd $PBS_O_WORKDIR

module purge
module load <MODULE>/<VERSION>

# Place workflow command below.
<COMMAND>
```

Example resource request from manual: `select=1:ncpus=48`.

### MPI-style single-node job using nodes/ppn syntax

Use for highly parallel MPI-style workloads launched with `mpirun`.

```bash
#!/bin/bash
#PBS -N <JOB_NAME>
#PBS -l nodes=1:ppn=<NPROC>
#PBS -l mem=<MEMORY>
#PBS -M <EMAIL>
#PBS -m abe

cd $PBS_O_WORKDIR

module purge
module load <MODULE>/<VERSION>

export OMP_NUM_THREADS=1
mpirun -np <NPROC> <MPI_COMMAND>
```

Manual example pattern:

```bash
#PBS -l nodes=1:ppn=48
#PBS -l mem=32gb
module load lammps/020823
export OMP_NUM_THREADS=1
mpirun -np 48 lmp -i input.in
```

## Workflow wrapper guidance

When generating repository scripts for metagenomics/bioinformatics on this HPC:

- Create PBS wrappers in `hpc/`.
- Keep main analysis commands in reusable shell/Python/R scripts; PBS files should mainly request resources, load modules, activate environments, and call the workflow.
- Use conservative first-pass resources, then scale after logs are inspected.
- For Python/R workflows, prefer conda/venv activation inside PBS script only after `cd $PBS_O_WORKDIR`.
- Do not assume Slurm commands (`sbatch`, `squeue`, `scancel`); this cluster uses OpenPBS commands (`qsub`, `qstat`, `qdel`).
- Do not hard-code local laptop paths. Use project-relative paths from `$PBS_O_WORKDIR`.
- Write logs to `logs/` when possible.
- Keep temporary large files in a project scratch/work directory if available; otherwise use explicit `work/` and document cleanup.

Suggested PBS wrapper skeleton for project pipelines:

```bash
#!/bin/bash
#PBS -N <PROJECT_STEP>
#PBS -l select=1:ncpus=<NCPUS>
#PBS -M <EMAIL>
#PBS -m abe

set -euo pipefail

cd $PBS_O_WORKDIR
mkdir -p logs results work

module purge
# module load <required_modules>

# Optional environment activation:
# source ~/.bashrc
# conda activate <ENV_NAME>

bash scripts/<pipeline_step>.sh \
  > logs/${PBS_JOBNAME}.${PBS_JOBID}.out \
  2> logs/${PBS_JOBNAME}.${PBS_JOBID}.err
```

## Jupyter via PBS

Optional manual-derived examples, not requirements of the released analytical
workflows. Verify the helper and runtime limits with the current cluster service.

Manual-provided helper command:

```bash
jupyter_run -n <NCPUS> -e <EMAIL>
```

Check help:

```bash
jupyter_run -h
```

Jupyter output is written to `jupyter.log`. Extract from `jupyter.log`:

- compute hostname, e.g. `orion1`
- node-side port, e.g. `8888`
- token from Jupyter URL

Port forwarding template from local machine:

```bash
ssh -L localhost:<LOCAL_PORT>:<COMPUTE_NODE>:<NODE_PORT> <hpc-login-node>
```

Manual example:

```bash
ssh -L localhost:8080:orion1:8888 <hpc-login-node>
```

Open locally:

```text
http://localhost:<LOCAL_PORT>/tree?token=<TOKEN_FROM_JUPYTER_LOG>
```

Default Jupyter runtime noted in manual: 3 days. Stop it through PBS:

```bash
qstat
qdel <JOB_ID>.<hpc-login-node>
```

Custom conda Jupyter PBS template:

```bash
#!/usr/bin/env bash
#PBS -l select=1:ncpus=<NCPUS>
#PBS -N <JOB_NAME>
#PBS -M <EMAIL>
#PBS -m abe

cd $PBS_O_WORKDIR

: > jupyter.log
echo "====================================================" >> jupyter.log 2>&1
echo " Date     : $(date +%Y/%m/%d)" >> jupyter.log 2>&1
echo " Time     : $(date +%H:%M:%S)" >> jupyter.log 2>&1
echo " Hostname : $HOSTNAME" >> jupyter.log 2>&1
echo "====================================================" >> jupyter.log 2>&1

source ~/.bashrc
conda activate <ENV_NAME>
python -m jupyter notebook --no-browser --ip=* >> jupyter.log 2>&1
```

## Cluster command reference

| Task | Correct behavior |
|---|---|
| Need to login | Use `ssh <hpc-login-node>` after SSH config exists |
| Need compute | Generate PBS script; submit with `qsub` |
| Need status | Use `qstat`, `qstat -n`, or `qstat -s` |
| Need cancel | Use `qdel <JOB_ID>` |
| Need modules | Use `module avail`, `module purge`, `module load` |
| Need Jupyter | Use `jupyter_run` or custom PBS Jupyter script |
| Need local browser to Jupyter | SSH port forward through `<hpc-login-node>` |
| Need Slurm | Use the separate Slurm launchers at a Slurm site; this cluster uses OpenPBS |
| Need heavy command on login node | Do not run; submit PBS job |
