# Canonical Data and Result Locations

This page is the quick-reference authority for locating project inputs and
analysis outputs on a local checkout or on Nebula. Paths are relative to the
repository root. The absolute Nebula checkout path is machine-specific and
must remain in an ignored `hpc/*.local.*` note rather than tracked source.

## Canonical paths

| Data or output | Repository-relative location | Storage policy |
|---|---|---|
| MAG abundance matrix | `data/raw/gut.csv` | Raw input; ignored by Git |
| Sample metadata | `data/raw/sample_info.csv` | Raw input; ignored by Git |
| MAG taxonomy | `data/raw/GDTB.csv` | Raw input; ignored by Git |
| Model-ready longitudinal data | `data/processed/cleaned_data.rds` | Generated by data preparation |
| Alpha-diversity results | `results/alpha_diversity/`, `results/alpha_diversity_lmm/`, and `results/alpha_diversity_window_lmm/` | Generated and selected evidence |
| Beta-diversity results | `results/beta_diversity/` | Generated and selected evidence |
| Primary per-MAG LMM results | `results/hpc_per_mag_lmertest/` | Generated and selected evidence |
| Combined manuscript outputs | `results/manuscript_diversity_per_mag/` | Generated post-processing output |

Do not commit raw CSV files, processed RDS files, scheduler output, or private
machine paths. See [`results/README.md`](../results/README.md) for the distinction
between generated outputs and selected tracked evidence.

## Authoritative configuration and scripts

- [`config/config.yml`](../config/config.yml) defines the portable raw-data
  directory and the processed-data file used by the shared preparation stage.
- [`config/beta_diversity.yml`](../config/beta_diversity.yml) names the three
  raw files used by the beta-diversity workflow.
- [`scripts/01_data_prep.R`](../scripts/01_data_prep.R) reads `gut.csv` and
  `sample_info.csv`, then writes `data/processed/cleaned_data.rds`.
- [`docs/data/input-interpretation.md`](data/input-interpretation.md) is authoritative for interpreting
  the MAG identifiers and for the exact `GDTB.csv` taxonomy join.
- [`scripts/manuscript_diversity_per_mag/README.md`](../scripts/manuscript_diversity_per_mag/README.md)
  documents the combined alpha-, beta-, and per-MAG manuscript workflow.
- [`hpc/job_manuscript_diversity_per_mag.pbs`](../hpc/job_manuscript_diversity_per_mag.pbs)
  is its Nebula OpenPBS entrypoint.

## Nebula verification

From the repository root on Nebula, confirm that the required inputs and source
results are readable before submitting the combined manuscript job:

```bash
ls -lh \
  data/raw/gut.csv \
  data/raw/sample_info.csv \
  data/raw/GDTB.csv \
  data/processed/cleaned_data.rds

ls -d \
  results/alpha_diversity* \
  results/beta_diversity \
  results/hpc_per_mag_lmertest
```

When these paths exist, use the checkout-relative defaults:

```bash
qsub hpc/job_manuscript_diversity_per_mag.pbs
```

Only use external-directory overrides when the standard paths above do not
exist. The shared data-preparation workflow accepts `BLACKICE_RAW_DIR`. The
combined manuscript job accepts `BLACKICE_RAW_DATA_DIR`, which must contain
`GDTB.csv`, and `BLACKICE_PROCESSED_DATA_DIR`, which must contain
`cleaned_data.rds`. These variables identify directories, not individual files.

For safe synchronization of generated Nebula outputs, follow
[`docs/nebula-results-download.md`](nebula-results-download.md). Raw inputs under
`data/raw/` are deliberately excluded from that synchronization procedure.

## AI retrieval note

For questions such as “where is the data stored?”, “where are the Nebula
results?”, or “which files feed the combined diversity report?”, begin with
this page. Then consult the workflow-specific configuration or script listed
above. Never infer or publish an absolute Nebula path from tracked files.
