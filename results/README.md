# Results Directory

This directory contains a mixture of generated working outputs and selected
tracked evidence. The presence of a file in Git, or in a local checkout, does
not by itself make that file the current scientific conclusion.

## Output policy

- `results/figures/`, `results/tables/`, and `results/logs/` are generic legacy
  output locations and retain `.gitkeep` placeholders.
- Workflow-specific directories group tables, figures, diagnostics, logs,
  sessions, models, reports, and reproducibility records.
- A completed subject-aware Random Forest run may contain a generated
  `manuscript/` subdirectory with reader-first figures, exact tables, panel
  data, and rendering metadata. These post-processing files do not replace the
  canonical predictions and comparisons in the parent run.
- Many large or routinely regenerated workflow outputs are ignored by
  `.gitignore`.
- `results/netmoss_matched_timepoint_companion/` is generated by the separate
  all-pairs abundance companion. Its genus-pair and participant-change tables
  are not NetMoss scores or network results.
- `results/netmoss_altitude/` is generated by the separate exploratory
  T1/T2/T9/T10 versus T3–T8 NetMoss scenario and must not overwrite or relabel
  the preserved outputs under `results/netmoss/`.
- `results/netmoss_altitude_stability/` contains generated resampling evidence
  for the separate altitude contrast. Passing its operational thresholds means
  internal reproducibility only, not independent biological validation.
- Selected alpha-diversity, manuscript-table, metadata-window, data-inspection,
  and per-MAG result artifacts were committed historically as analysis
  evidence. Do not remove or regenerate them as repository tidying.

## Safe handling

- Do not manually edit generated CSV, figure, model, or session files.
- Do not assume a clean Git checkout after running an analysis: some tracked
  evidence files may be regenerated by their source scripts.
- Review `git status` before and after every run.
- Never use a broad cleanup command against this directory without resolving
  its exact targets and confirming that retained evidence is recoverable.
- Keep raw data and credentials out of results and logs.
- `results/mag_functional_annotation/` is a generated Nebula-only workflow
  directory. Its local/HPC `RESULTS_INDEX.md` is generated for navigation but
  the directory, matrices, figures, and tables are not selected Git evidence.
- `results/manuscript_functional_synthesis/` is generated post-processing. Its
  figure, table previews, editable CSV/TSV tables and panel data remain
  uncommitted; the tracked source of interpretation is the corresponding
  document under `docs/manuscript-drafts/`.

## Interpretation

Use the repository [README](../README.md), [decision log](../docs/public-release-policy.md),
workflow documentation, and analysis reports to determine status and
interpretation. Raw `p < 0.05` candidate outputs remain exploratory unless the
documented multiple-testing rule is satisfied.

## Reproducibility

When a workflow supports it, retain its configuration, Git commit, scheduler
metadata, session information, input checksums, and execution record together.
See [HPC Execution Recording](../docs/hpc_execution_recording.md) for the shared
record format.
